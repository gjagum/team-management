# Deno Deploy Guide

## Architecture

The application is deployed as a **single Deno server** that serves both the API
and the built frontend.

```
backend/
├── src/index.ts    ← Server entry point (API + static file serving)
├── src/routes/     ← API route handlers
├── prisma/         ← Database schema
└── static/         ← Built frontend (generated by deno task build)
```

---

## Prerequisites

- [Deno](https://deno.land/) installed locally
- Deno Deploy account at [console.deno.com](https://console.deno.com)
- Neon PostgreSQL database (or compatible)

---

## Initial Setup (One-time)

### 1. Create the app

```bash
deno deploy create team-management
```

### 2. Set environment variables

In the Deno Deploy dashboard → Environment Variables:

| Variable       | Value                                  |
| -------------- | -------------------------------------- |
| `DATABASE_URL` | Your Neon PostgreSQL connection string |
| `JWT_SECRET`   | A strong random secret (32+ chars)     |

### 3. Configure App Settings

In the Deno Deploy dashboard → App Configuration:

| Field               | Value                                                                                                 |
| ------------------- | ----------------------------------------------------------------------------------------------------- |
| **Install command** | `deno install --allow-scripts=npm:@prisma/client@5.22.0,npm:@prisma/engines@5.22.0,npm:prisma@5.22.0` |
| **Build command**   | `deno run -A npm:prisma generate && deno run -A npm:prisma db push --accept-data-loss`                |
| **Entrypoint**      | `src/index.ts`                                                                                        |

### 4. Push database schema

```bash
cd backend
DATABASE_URL="your-neon-connection-string" npx prisma@5.22.0 db push --schema=./prisma/schema.prisma
```

### 5. Seed the database

```bash
cd backend
DATABASE_URL="your-neon-connection-string" deno task seed
```

## Deploy Workflow

Every time you want to deploy changes:

```bash
cd backend

# 1. Build (frontend + prisma)
deno task build

# 2. Deploy
deno deploy --app=team-management --prod --allow-node-modules --no-wait
```

`deno task build` does three things:

1. Builds the React frontend via Vite (`frontend/dist/`)
2. Copies built files to `backend/static/`
3. Generates the Prisma client

## Troubleshooting

### Build fails

- Check that **Install command** includes `--allow-scripts` for Prisma packages
- Verify **Entrypoint** is `src/index.ts`
- Check build logs in the dashboard

### Database connection issues

- Verify `DATABASE_URL` is set in Deno Deploy environment variables
- Ensure `?sslmode=require` is in the connection string
- **Neon Pooler**: If your `DATABASE_URL` contains `-pooler`, you **must** append `&pgbounce=true` to avoid the "cached plan must not change result type" error after schema changes.
- Check that Neon database is active (not suspended)

### Frontend not loading

- Run `deno task build` before deploying
- Verify `backend/static/` contains `index.html` and `assets/`

### API returns HTML instead of JSON

- API routes must be defined **before** the static file catch-all in
  `src/index.ts`
- Check route paths match (e.g., `/api/users` not `/users`)
